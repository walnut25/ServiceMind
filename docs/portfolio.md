# 项目介绍（求职版）

## 一句话

在开源的 AI 工单系统 ServiceMind（Java 21 + Spring Boot 3.5 + React + MySQL）之上，**从零搭建了一套独立的
Python 自动化测试工程**：179 条用例覆盖接口、业务状态机与浏览器主流程，接入 Allure 报告与 GitHub Actions，
并通过测试固定了 4 个真实行为差异、另记录 4 条代码审计发现与 5 处文档/实现不一致。

## 背景与目标

ServiceMind 原本只有 42 个 Java 单元测试和 4 个 Testcontainers 集成测试，且全部集中在领域层与仓储层：

- 没有任何一条测试真正走 HTTP → 登录、鉴权、错误码映射、状态机边界全是盲区；
- 没有跨角色的权限矩阵验证；
- 没有浏览器端回归能力；
- CI 不产出测试报告。

目标是在**不修改业务代码**的前提下，补齐"从外部看系统"的验证能力，并让它成为可持续运行的工程资产，而不是一次性脚本。

## 我做了什么

### 1. 先审计，后动手（两天工作量的 1/3 花在这里）

通读 51 个后端源文件（23 个接口）、6 个 Flyway 迁移、React 全部路由与页面、Compose 与 CI 配置，输出：

- 23 个接口的完整契约（路径、角色、参数、状态码、错误体）；
- 工单状态机的真实邻接表（与 Swagger 注解不符）；
- 6 类业务异常到 HTTP 状态码的映射；
- 前端 10 条路由与角色守卫的实际行为（含"`/tickets` 没有角色守卫"这类细节）；
- 现有测试的真实覆盖与缺口（例如登录端点零测试）。

这份审计直接决定了用例设计——**每一个断言都能指回某一行源码**。

### 2. 搭建可演进的测试框架（而不是一堆脚本）

- **统一 `ApiClient`**：基址、超时、鉴权头、耗时与日志集中管理，失败自带请求/响应上下文；
- **断言分层**：状态码 → RFC 9457 `title/detail` → 业务字段 → jsonschema；
- **认证 fixture**：会话级登录复用，角色账号按需创建，JWT 可自签以构造过期/篡改/无 scope 场景；
- **数据策略**：没有删除接口，就用全局唯一命名 + 只碰自建数据 + CI 全新数据库卷；
- **UI 层**：一个内置的「静态站点 + /api 反代」服务替代 nginx/vite，测试无需构建缓存写入仓库；
  针对 antd 把「登录」渲染成「登 录」的问题写了容错定位器，而不是退回不稳定的 XPath。

### 3. 覆盖真正会出问题的地方

- 状态机 8 条非法流转逐条断言 409，并验证**失败不产生审计事件**；
- 指派接口「非法负责人 422 优先于工单不存在 404」的顺序契约；
- REQUESTER 读他人资源返回 **404 而非 403**（不泄露存在性）与写操作 403 的区别；
- 知识库"已发布仍可编辑、仅归档冻结"这条容易被误解的规则；
- 评论不刷新工单 `updatedAt`、`version` 单调递增这类隐性契约；
- AI 模块不依赖真实大模型：用「无命中 200」与「命中但未配置 503」两条确定性路径覆盖。

### 4. 工程化收尾

- Allure 报告（成功率、耗时、步骤、失败堆栈、UI 失败截图）；
- 独立 GitHub Actions 工作流：API 与 UI 两个 Job 并行，互不掩盖，失败自动收集容器日志；
- 文档：架构说明、179 条用例清单、已知问题、本地/Docker/CI 三套运行手册。

## 可以展开讲的技术判断

1. **为什么不用 Mock**：MockMvc 已经存在但绕过了真实 JWT 与 Filter 链；黑盒测试的价值恰恰在于覆盖这些"胶水层"。
   需要隔离时（AI 供应商）优先用系统自带的确定性分支，而不是 mock 掉整个业务逻辑。
2. **为什么坚持用真实 MySQL**：全文检索是 `MATCH ... AGAINST` 原生 SQL，换 H2 就测不到真实行为。
3. **测试数据怎么隔离**：没有删除接口时，"唯一命名 + 只碰自己创建的数据 + 每次全新库"比"想办法清理"更可靠。
4. **失败怎么定位**：断言失败必须自带响应体；UI 失败必须带截图与控制台日志；CI 失败自动 dump 容器日志。
5. **哪些问题不该写成用例**：需要篡改数据库或等待 30 分钟才能复现的，写进文档而不是硬塞进套件——测试套件要稳定，
   缺陷记录要准确，两者不混。

## 已知局限

- 本机 Windows 受限令牌下 Playwright 驱动无法启动，UI 用例需在普通终端或 CI 中运行（已在文档说明）；
- 乐观锁、token 吊销、last-admin 保护这三项属于代码层缺陷，未纳入自动回归（原因见 `known-issues.md`）；
- 未做性能与安全扫描（不在本次范围）。
